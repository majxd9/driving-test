# رخصتي — تطبيق أندرويد 📱

تطبيق صغير يفتح موقع رخصتي (`driving-test-7en.pages.dev`) داخل التطبيق، ويمنع لقطة الشاشة وتسجيل الشاشة (FLAG_SECURE).

**ما لمسنا كود الموقع أبداً** (`client` و`server`). إذا صار أي شي بالتطبيق، الموقع يضل شغال متل ما هو، وأي تعديل بالموقع بيظهر بالتطبيق لحاله — ما بتحتاج تعيد بناء الـAPK.

## وين أحط المجلد؟

```
driving-test/
├── client/
├── server/
├── android/                            ← هذا المجلد
└── .github/workflows/android-apk.yml   ← يبني الـAPK تلقائياً على GitHub
```

## شو فيه؟

- الموقع نفسه بدون أي تعديل: تسجيل الدخول، الأسئلة، التدريب، الإشارات، الصور، الصوت، لوحة الإدارة.
- تسجيل الدخول يبقى محفوظ (الكوكيز والتخزين شغالين، بما فيها كوكيز الـAPI على Render).
- زر الرجوع يمشي داخل الموقع، وبالصفحة الأولى ضغطتين للخروج.
- روابط الموقع تنفتح داخل التطبيق، وأي رابط تاني (واتساب، اتصال، مواقع خارجية) ينفتح بالتطبيق المناسب.
- شاشة تحميل بألوان الموقع، وشاشة «تعذّر التحميل» عند انقطاع النت، والصفحة بتنعاد لحالها لما يرجع النت.
- تدوير الشاشة أو تغيير حجم الخط ما بيعيد تحميل الصفحة (ما بتضيع على الطالب أسئلة الاختبار).
- إذا الأندرويد أغلق التطبيق بالخلفية، بيرجع لنفس الصفحة، وإذا تعطّل محرك WebView ما بيسكّر التطبيق.
- أيقونة وشاشة بدء بنفس هوية الموقع (سيارة الـfavicon)، وأيقونة متوافقة مع الثيم على أندرويد 13+.
- يشتغل من أندرويد 7.0 وما فوق.

## طريقة 1 — Android Studio (على الكمبيوتر)

1. نزّل **Android Studio** من الموقع الرسمي وثبّته بالإعدادات العادية.
2. `File → Open` واختار مجلد **android** (مو مجلد المشروع كله). استنى لحد ما يخلص الـSync — أول مرة بينزّل ملفات كتير (حوالي 1 جيجا)، خليه لحاله.
3. من `View → Tool Windows → Build Variants` اختار **release** للـ`app`.
4. `Build → Build APK(s)` — لما يخلص اضغط **locate**. الملف:
   `app/build/outputs/apk/release/app-release.apk`

## طريقة 2 — GitHub (بدون ما تثبّت أي شي)

1. انسخ المجلدين `android` و`.github` إلى مجلد المشروع `driving-test`.
2. من داخل مجلد المشروع:
   ```
   git add android .github
   git commit -m "Add Android app"
   git push
   ```
3. على GitHub افتح تبويب **Actions** ← **Build Android APK**. بيشتغل لحاله بعد الـpush، أو اضغط **Run workflow**.
4. بعد حوالي 5 دقايق افتح العملية الناجحة ← أسفل الصفحة **Artifacts** ← `Rukhsati-APK` ← نزّله وفك الضغط، فيه `app-release.apk`.

## تثبيت الـAPK على الموبايل

انقل الملف للموبايل وافتحه. إذا طلب الأندرويد إذن، اسمح بـ«التثبيت من هذا المصدر».

## اختبار قبل ما توزّع التطبيق (5 دقايق)

- [ ] تسجيل الدخول، ثم إغلاق التطبيق وفتحه: لازم يبقى مسجّل
- [ ] تسجيل الخروج
- [ ] الانتقال بين الصفحات + زر الرجوع
- [ ] الأسئلة والصور والإشارات
- [ ] التدريب والاختبار + الصوت
- [ ] لقطة الشاشة: لازم تفشل أو تطلع سوداء
- [ ] تسجيل الشاشة: لازم يطلع أسود
- [ ] قائمة التطبيقات الأخيرة: معاينة التطبيق مخفية
- [ ] تدوير الشاشة: الصفحة ما تنعاد
- [ ] فصل الإنترنت: تظهر «تعذّر التحميل»، وترجع الصفحة لحالها لما يرجع النت
- [ ] لوحة الإدارة (إذا بتستخدمها من التطبيق)

## بدك تغيّر شي؟

| بدك | وين |
|---|---|
| رابط الموقع | `app/build.gradle.kts` ← `siteUrl` |
| نطاق جديد ينفتح داخل التطبيق (مثلاً دومين خاص) | `app/build.gradle.kts` ← `internalHosts` |
| اسم التطبيق | `app/src/main/res/values/strings.xml` ← `app_name` |
| إيقاف منع اللقطات مؤقتاً | `app/build.gradle.kts` ← `blockScreenshots = false` |
| قفل الشاشة عمودي | `AndroidManifest.xml` ← أضف `android:screenOrientation="portrait"` للـactivity |
| رقم الإصدار | `app/build.gradle.kts` ← `versionCode` و`versionName` |

كل تعديل بهدول بيحتاج بناء APK جديد (تعديلات الموقع نفسه لا).

## ملاحظات مهمة

**1) حدود FLAG_SECURE.** بيمنع اللقطة والتسجيل والبث **داخل التطبيق** فقط. ما بيمنع تصوير الشاشة بكاميرا موبايل تاني، وما بيحمي الموقع إذا انفتح من Chrome (هناك تضل حماية الـJavaScript فقط). وعلى موبايل معمول له root ممكن يتم تجاوزه.

**2) ربط الحساب بالجهاز.** التطبيق له تخزين مستقل عن Chrome، فالموقع بيشوفه «جهاز جديد». طالب سجّل من Chrome وبعدين ثبّت التطبيق (أو مسح بيانات التطبيق أو أعاد تثبيته) لازم تعمل له **إعادة ضبط الجهاز** من لوحة الإدارة.

**3) الموقع يعرف إنه تطبيق.** التطبيق بيضيف `RukhsatiApp/1.0.0` لآخر الـUser-Agent. ممكن يفيدك مستقبلاً إذا بدك الموقع يتصرف بشكل مختلف داخل التطبيق.

## توقيع ثابت (مرة وحدة، قبل ما توزّع على الطلاب)

**ليش؟** بدونه كل APK جديد بينبني بتوقيع مختلف، والطالب لازم يحذف القديم ويثبّت الجديد (وبيخسر ربط الجهاز).

1. أنشئ المفتاح مرة وحدة، واحفظ الملف والباسوورد بمكان آمن (ولا ترفعهم على GitHub):
   ```
   keytool -genkeypair -v -keystore rukhsati-release.jks -alias rukhsati -keyalg RSA -keysize 2048 -validity 36500
   ```
   الأداة `keytool` موجودة داخل Android Studio: مجلد `jbr/bin`.
2. ضع الملف `rukhsati-release.jks` داخل مجلد `android`، وأنشئ بجانبه ملف `keystore.properties`:
   ```
   storeFile=rukhsati-release.jks
   storePassword=كلمة_السر
   keyAlias=rukhsati
   keyPassword=كلمة_السر
   ```
   الملفان محميّان من الرفع بواسطة `.gitignore`. من هون Android Studio بيوقّع تلقائياً.
3. للبناء على GitHub: `Settings ← Secrets and variables ← Actions` وأضف أربعة Secrets:
   `KEYSTORE_BASE64` (ناتج `base64 -w0 rukhsati-release.jks`)، `KEYSTORE_PASSWORD`، `KEY_ALIAS`، `KEY_PASSWORD`.

## إذا صار معك خطأ

- **SDK location not found**: افتح مجلد `android` من Android Studio نفسه (هو بينشئ الإعداد لحاله).
- **Gradle sync failed**: تأكد من الإنترنت وأعد المحاولة (`File ← Sync Project with Gradle Files`).
- **Unsupported JDK / Java version**: `Settings ← Build Tools ← Gradle ← Gradle JDK` واختار الـJDK المدمج مع Android Studio (jbr).
- الأخطاء على GitHub: افتح العملية الفاشلة وانسخ آخر 30 سطر من خطوة **Build release APK**.
